How to reduce image file size without ruining quality

A phone photo is often several megabytes, far more than a web page, an email or an upload form needs. Four things decide a file size. Working through them in this order gets the biggest saving for the least damage.

1. Dimensions: fewer pixels

File size grows with the number of pixels, which is width times height. Halving both sides leaves a quarter of the pixels. A photo taken at 4000 x 3000 pixels is 12 million pixels, far more than a screen needs; scaled to 1600 pixels wide it is about 1.9 million. Resizing is the biggest lever and costs the least visible quality. Use the image resizer.

2. Format: pick the right one

  • JPEG suits photos. It discards detail the eye barely notices, so files are small, and it is accepted everywhere. It has no transparency.
  • PNG is lossless and keeps transparency, which makes it ideal for logos, screenshots and text, and large for photos.
  • WebP makes smaller files than JPEG or PNG at similar quality and supports transparency, but some older programs and upload forms reject it.

A photo saved as PNG is usually many times larger than the same photo as JPEG. Convert with the PNG to JPG converter.

3. Quality: lower it, but not too far

JPEG and WebP have a quality setting. The first reductions save a lot of space with little visible change; past a point the savings shrink and blocky artefacts appear. A setting in the range of 75% to 85% is a sensible place to start, then look at the result. The image compressor shows the before and after sizes so you can decide.

4. Metadata: strip what you do not need

Photos carry extra data such as the camera model and, often, GPS location. It is usually small, but removing it is good for privacy. Saving an image through a canvas, as these tools do, drops it.

Compress to an exact size

When a form or site has a limit, such as 100 KB, 50 KB or 20 KB, the tool searches for the highest quality that fits, and reduces dimensions in steps if quality alone is not enough. Always keep the original, because lossy compression cannot be undone.

Worked example: why resizing comes first

An uncompressed colour image stores about 3 bytes per pixel (one each for red, green and blue). A 4000 x 3000 photo has 12,000,000 pixels, so before compression it is about 36 MB. Scaled to 1600 x 1200 it has 1,920,000 pixels and is about 5.8 MB uncompressed, 16% of the original (1,920,000 / 12,000,000). JPEG then compresses what is left; the ratio depends heavily on the picture, with detailed scenes compressing less than plain ones, so the only reliable way to know the final size is to save it and look. The point of the arithmetic is the direction: the number of pixels is multiplied by the quality setting, not added to it, so cutting pixels first leaves less for the quality setting to have to cut.

Common mistakes

  • Compressing the same file again and again. Each save of a JPEG discards a little more detail. Always start from the original file, and compress once.
  • Renaming instead of converting. Changing photo.png to photo.jpg in the file name does not change the data inside, and many forms inspect the content, not the name.
  • Making a small image bigger. Scaling up adds pixels but no detail, so the file grows and looks soft. Resize down only.
  • Using PNG for photographs. PNG stores every pixel exactly, so photographs are large; it earns its size on logos, screenshots and text.
  • Expecting transparency after converting to JPG. JPEG has none; transparent areas are filled with a background colour (white in these tools).

What the quality number means

The quality value you set is passed to the browser's own image encoder as a number between 0 and 1 (the quality argument of canvas.toBlob, documented by MDN at developer.mozilla.org). It is not a percentage of the original size, and the same number can give slightly different files in different browsers, because each browser uses its own encoder. That is why the tools show the real size after encoding instead of promising one.
